# 原理图解析与 PCB Layout 方法调研

调研日期：2026-09-23。依据本地赛题资料、压缩包实测、EDA 官方文档和论文。商业工具功能来自厂商说明，未在本机进行产品性能对比；研究建议是本报告的判断，不代表已经实现或验证。

## 1. 结论与任务边界

本文件夹对应的比赛是“原理图图片 → 元器件、引脚、网络及线段 JSON”，不是自动生成 PCB。它可以成为 schematic-to-layout 系统的入口，但当前数据不包含完成物理设计所需的封装、焊盘映射、板框、叠层和电气约束。

建议分两条路线推进：竞赛以“视觉解析 + 显式拓扑恢复 + 局部多模态纠错”为主；延伸研究以“电路设计意图 → 可执行约束 → EDA 引擎闭环布局布线”为主。先做可信的网表和评测，再连接物理设计工具。

### 2.1 评分决定技术优先级

中文指南第 5–8 页规定：

- 单例准确度 = 100 ×（0.30 ComponentF1 + 0.25 PinF1 + 0.35 NetHypergraphF1 + 0.10 NetLineF1）。
- 准确度部分最终分数 = 0.95 × 案例准确度分 + 0.05 × 完成比例 × Token 分。
- 另有最多 10 分的数据贡献分。
- 总评测时限小于 2 小时，预计 30–50 例，公开与黑盒比例 1:2，中等与难例比例 40%:60%。
- 元件框默认容差 20 px，引脚和线段端点默认容差 5 px；文本严格匹配。
- 元件 key 和 pin number 错误会连带损害 pin 和 net 得分。

因此，不能只优化元器件检测 mAP。引脚身份、全局 net 合并、位号和文字绑定更值得投入。大模型应有按例预算、超时回退和失败检查点；Token 分是相对赋分，不应为省少量 Token 牺牲大量准确度。

指南提到 qwen3.7-plus API 测试环境，这里只是转述本地文档，未实测平台端点、模型能力或可用配额。

### 2.2 实测发现的关键问题

1. **Golden Case 与训练集重叠。** 按 PNG 文件字节的 SHA-256 检查，10 个 Golden Case 全部在训练集出现。训练集内部另有 0118/0142、0139/0194 两组完全相同的图片。200 个训练记录实际有 198 个字节级唯一图像；加入 Golden Case 后唯一图像数仍为 198。该检查尚不包含缩放、压缩或裁剪产生的近重复。
2. **同图标注版本不同。** 抽查 0025 的训练与 Golden JSON 不相同：部分匿名元件 key、pin key、pinname、bbox 和 value 有差别。不能把同图两份标注直接视为一致真值；更不能用 Golden Case 成绩宣称独立泛化能力。
3. **实际文件名与 README 示例不同。** 200 个训练 JSON 都是 `*_target_named.json`，Golden 是 `*_target.json`。应按 case 目录配对，不能只依赖 README 示例后缀。
4. **类别枚举不一致。** 实际数据常见 `r/c/box/v/gnd`；PDF 描述使用 `resistor/capacitor/ic` 等。不能直接全局替换，尤其 `box` 是否一律对应 IC 需要核对。应建立保留原始值的适配层，并以正式评分器验证。
5. **坐标规定冲突。** PDF 第 11、26 页写明左下角原点、y 向上；0915 新增数据提交指南要求左上角原点、y 向下，绝对坐标必须是整数；README 允许浮点数。对 0025 进行标注框叠图，左下角解释能对齐图像。这个抽查不能证明所有样本都一致，也不能确定正式预测接口是否已改版。
6. **标注身份未必等于物理引脚身份。** 抽查样本出现 `∅75` 等匿名 key，以及开关的 `pin_66`、`pinname=P_13`。在将赛题 JSON 用于 PCB 时，必须重新核验真实符号引脚号与封装 pad number，不能把标注内部 ID 当成封装脚号。

全量记录的规模范围为：每例 5–185 个 components、18–393 个 pins、6–206 个 nets。这些是赛题标注对象计数，包含地符号、网络标签等，不能直接当作真实 BOM 数量。全部 PNG 均可由 Pillow 解码。

建议将坐标、类别、匿名编号、文本保真、线段分段方式列成规则对照表，配一组可视化样例，在拿到最新 Q&A 和官方评分器后锁定接口。内部使用统一表示，分别输出比赛预测格式和新增数据提交格式。坐标翻转还要核验 H-y 与 H-1-y 的像素约定，不能机械套公式。

数据检查明细保存在同目录 `dataset_audit.json`。原文件未修改。

### 2.3 新增数据贡献

0915 指南要求至少 20 个有效、与训练集不重复的案例，包含可核验的 IC、至少 5 个有效元件、至少 5 个唯一有效 net，并满足分段 IC 有效引脚门槛。抽检数为 max(20, ceil(有效案例数 × 10%))；批次连接 F1 不低于 95%，单例不低于 85%，另需通过标注一致性检查。

贡献分为 10 × Q_i / Q_max，因此“提交 20 例”只是资格门槛，不保证 10 分。本地指南写明最终截止为 2026-11-08 23:00，提前一周节点为 2026-11-02 23:00；日期尚未用比赛平台公告复核。

## 3. 从 schematic 到 Layout 的业界流程

### 3.1 原理图到 PCB 的中间信息

网表描述“哪些引脚属于同一网络”。PCB 还需要知道元件封装、焊盘位置和层、板框、机械限制及电气约束。原理图中的器件位置和导线折线主要服务阅读，不能作为 PCB 元件位置与铜线几何的直接答案。

例如，同一个连接关系可以采用不同封装、不同层数和不同接口位置，产生多种合法布局。SPICE 网表还可能按仿真模型的端子顺序表示器件，不能保证已包含 PCB pad 映射。

业界工具通过项目数据库、网表同步或工程变更单（ECO）把符号、封装和网络对应起来。Altium 的 Constraint Manager 支持从原理图到 PCB 的约束管理；KiCad 支持从原理图更新 PCB、交互式布线和设计规则检查。参见 [Altium Constraint Manager](https://www.altium.com/documentation/altium-designer/sch-pcb/constraint-manager) 和 [KiCad PCB Editor](https://docs.kicad.org/9.0/en/pcbnew/pcbnew.html)。

### 3.2 工程步骤与交付物

| 阶段 | 要解决的问题 | 交付或验证 |
|---|---|---|
| 原理图与库审查 | 位号、器件型号、引脚类型、封装和 pad 映射是否正确 | ERC、BOM、符号与封装核验 |
| 机械与制造输入 | 板框、连接器、孔、限高、禁布区、层数、材料、铜厚 | 可执行板级边界与叠层 |
| 电气约束 | 哪些信号需阻抗、时延、等长、隔离、电流和温升约束 | net class、差分对、约束集 |
| 布局 | 功能分区、关键回路、去耦、散热与可布线性 | 合法布局和人工审查 |
| 布线 | 扇出、关键网络、一般网络、电源地、过孔及长度调整 | 已连接的板级铜几何 |
| 检查与分析 | 几何规则、原理图一致性、信号/电源完整性及热风险 | DRC、按需求开展的 SI/PI/热验证 |
| 制造交付 | 裸板制造、装配、测试信息 | Gerber/钻孔或约定交换格式、BOM、贴片坐标、图纸 |

这是一套综合工程流程，不意味着每块低速简单板都要完整电磁仿真。检查深度应由速度、功率、密度和应用要求决定。

布局不宜只优化最短连线：去耦环路、开关电源高 di/dt 回路、敏感模拟信号和连续参考平面会改变最优位置。TI 指南特别强调高速信号的回流路径和参考设计复用，参见 [High-Speed Layout Guidelines](https://www.ti.com/lit/an/scaa082a/scaa082a.pdf)。

### 3.3 传统自动化算法怎样发挥作用

典型算法家族包括：功能分组和图划分、模拟退火或其他搜索式布局、基于线长/拥塞的优化与合法化；布线中的迷宫搜索、A*、多端点连接树、拥塞代价、拆线重布和局部优化。不同 EDA 产品具体实现并不公开，不能据此断言它们使用同一算法。

实际可复现的开源基线是：完成封装与布局后，由 KiCad 导出 DSN，交给 Freerouting，导回 SES，再做规则检查。Freerouting 官方说明支持该交换流程；它本身不是原理图图像识别器，也不能补齐缺失的设计意图。[Freerouting](https://github.com/freerouting/freerouting)

### 4.3 与真正 Layout 自动化相关的研究

**EDA 引擎闭环 agent。** PCBWorld 将代理动作落在 KiCad 原生布线操作上，接受 DRC 反馈，提供合成板和 679 块真实开源板。其论文报告学习策略接近规则路由器，而不是已经全面超越规则方法。它比“让 LLM 一次写出所有铜线坐标”更适合作为可执行研究起点。其重点是布线，不能直接当作从未布局网表到整板输出的完整方案。[PCBWorld 论文](https://arxiv.org/abs/2607.05915)、[代码](https://github.com/LGAI-Research/PCBWorld)

**元件级强化学习布局。** Component Centric Placement 研究 PCB 元件放置问题。借鉴时应检查是否覆盖双面、板界、重叠与布线约束，并以实际布通率验证收益；线长降低本身不能证明整体电气质量更好。[论文](https://arxiv.org/abs/2602.23540)

**工程理解基准。** PCB-Bench 包含文本、多模态题及 174 个真实 PCB 项目，适合评估 PCB 知识与理解。但答题能力和对既有设计的理解，不能替代自动生成板子的制造与功能验证。[PCB-Bench](https://digailab.github.io/PCB-Bench/)

不要把芯片 placement/routing 论文的结果直接迁移成 PCB 性能结论：PCB 的封装、连接器机械固定、双面装配、回流、电源和制造约束与标准单元设计不同。

## 5. 建议的可落地技术路线

### 5.1 竞赛主线

1. **先锁定数据协议。** 建立 PNG/JSON 读取、可视化叠图、身份与坐标适配；检查引用存在、pin key 稳定、每条 edge 恰为两点。保留零长度线段，不能一概删掉。
2. **建立三种基线。** 整图 VLM 作为性能与成本参照；检测/OCR/线网恢复的混合基线；混合基线加局部 VLM 纠错。所有基线使用相同案例、时间预算和评分脚本。
3. **分离视觉与电气拓扑。** 检测符号、文字、引脚、junction、线段；构造几何图；结合 junction 和交叉证据判断连接；再按标签语义和作用域合并为 net 超图。
4. **正确处理分块。** 高分辨率图用重叠切片保留小引脚和小字，恢复全图坐标后做去重与跨片线网拼接。否则局部识别提高而全局连接变差。
5. **大模型按不确定性调用。** 对低置信度型号、引脚文字、文本绑定和歧义 junction 发起局部图像查询；缓存结果并设置重试上限。不能让模型根据“常见电路”改写图中真实但不常见的连接。
6. **以图级错误分析驱动迭代。** 记录 key 错误、pin 错误、net 误合并、net 拆分、文本错误与坐标错误。优先修复能影响多个评分项的根因。

对非 VCC/GND 同名标签的“飞线”和零长度 edges，按照赛题规范单独实现。该规则是比赛序列化约定，不应和 PCB 软件中表示未布线连接的 ratsnest 混为一谈。跨页网名也必须考虑局部/全局作用域，不能只按字符串无条件合并。

独立验证集按项目/来源和图像重复簇划分。建议从 198 个唯一训练图像中留出验证部分，并保留跨来源测试；Golden Case 只做接口回归。若合成数据，优先从有许可的原生 CAD 自动导出图片和真值，再生成字体、颜色、分辨率与压缩扰动；不要只制造容易识别的干净图。

### 5.2 从比赛成果接到 PCB

建立独立的工程中间表示，至少包括：真实器件实例、型号、符号与封装引用、symbol pin 到 pad 的映射、net 成员、源图证据及置信度。标签和地符号保留为逻辑对象，不应全部实例化为物理封装。

随后补入板框、叠层、固定器件和电气约束；导出可被 KiCad 打开的工程；先在人审布局上验证自动布线与 DRC，再研究自动布局。这有助于区分“解析错误”“映射错误”“布局不可布”和“路由策略失败”。

开始时选明确封装和板框的小型低速电路。对关键型号或脚号不确定的案例，应输出待确认项，而不是生成貌似完成的生产文件。

## 6. 值得研究的创新方向

以下为研究建议，不是已得到实验结果的结论。

| 方向 | 具体问题 | 可验证实验 | 优先级 |
|---|---|---|---|
| 拓扑约束下的图像解析 | 局部文字/线条有歧义时，如何联合推断实体身份与全局 net | 与独立模块串联比较 NetHypergraphF1、整图完全正确率、误合并率 | 高，直接服务比赛 |
| 不确定性驱动的局部 VLM | 哪些局部值得消耗模型预算 | 同 Token/时间预算比较评分；去掉置信度调度做消融 | 高，贴合比赛成本项 |
| 数据手册到约束编译 | 将去耦、阻抗、回路、隔离等要求转成有出处的机器约束 | 约束提取准确率、误约束率、规则可执行率、人审时间 | 高，连接解析与 Layout |
| 原生 EDA 闭环修复 | 根据 DRC/未连接报告选网络、拆线重布、回退修改 | 对比固定策略和 Freerouting；统计 clean pass、布通率、时间与过孔 | 中高，适合 Layout 延伸 |
| 可复用功能块布局 | 检索参考电路的布局，按参数和封装变化迁移 | 按项目分割防止泄漏，对比从零布局的成功率和修改成本 | 中，工程价值明确 |
| 电气风险与布局联合优化 | 网表连通相同但回流/环路不同，如何让优化目标反映差异 | 分析回路、参考平面与仿真指标，再做少量实板对照 | 中长期，验证成本较高 |
| 从零训练通用整板生成模型 | 直接输出所有器件和铜线几何 | 需要大规模真实约束数据和强基线，当前文件夹数据无法支撑 | 当前不优先 |

可把总目标写为在硬约束满足条件下，优化线长、过孔、拥塞、运行时间和电气指标的多目标问题。几何合法性用精确检查；昂贵物理指标可用代理模型筛选，但最终仍需要相应分析或测量验证。不要让加权总分掩盖短路、断路等硬失败。

## 7. 验证与执行顺序

比赛阶段报告官方四项 F1、整图完全正确率、跨来源表现、平均及高分位耗时、Token 和超时比例。Layout 阶段报告未连通数、短路/DRC、完成率、线长、过孔数及所声明的电气指标；比较相同板框、封装、叠层和规则，控制搜索时间和候选数量。

推荐顺序：数据与规则审计 → 可运行混合解析基线 → 局部纠错和拓扑消融 → 有许可的原生工程扩充数据 → KiCad 工程桥接 → 固定布局路由基线 → agent 修复或自动布局研究。

近期最有价值的交付是可靠解析器、独立评测集和可追溯错误分析。中期研究题目可定义为“由原理图证据与器件知识约束的可验证 PCB 设计自动化”，明确覆盖哪些步骤、保留哪些人工输入，以实际 CAD 输出和验证结果衡量进展。
