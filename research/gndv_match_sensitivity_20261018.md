# GND/VCC 坐标匹配的**阈值敏感性**：46.79% 强依赖 20px

日期：2026-10-18。只读复算既有缓存，0 API、0 训练、未改预测/GT。
背景：codex 复核得到 256 个同类型、一对一几何匹配，假设性 macro ComponentF1 = 46.79%。
本文件补一个它没覆盖的问题：**这些匹配在更严的 bbox 阈值下还剩多少。**

## 方法

- 预测源：`outputs/unresolved_identity_recovery_20261017/cache_plus_new_keys/predictions`（1040 框）
- GT：dev20 的 931 个元件，其中 `gnd`+`v` 共 301 个
- 别名：`power_port → v`、`ground → gnd`
- 匹配：同类型、一对一、贪心取最小 max-corner 误差

## 结果

| bbox 阈值 | 命中 | 占 256 的比例 |
|---|---:|---:|
| ≤ 1px | 0 | 0.0% |
| ≤ 2px | 0 | 0.0% |
| **≤ 5px** | **41** | **16.0%** |
| ≤ 10px | 98 | 38.3% |
| ≤ 20px | **256** | 100% |

误差中位数 **11.61px**；GT 的 gnd/v 符号短边中位数 **19.0px**。

有符号偏移（预测 − GT，中位数）：`x1 +1.9`、`y1 +2.5`、`x2 −1.2`、`y2 +0.3`。
即我们的框比 GT **略窄约 3px、整体上移约 2.5px**，但**不存在可以一键补偿的常数偏置**——11.6px 的中位误差来自形状/尺度差异，不是平移。

## 结论

1. **46.79% 完全建立在"官方 bbox 容差是 20px"这个假设上。** 若实际是 5px（用户粘贴的平台说明里出现过 5px 字样，虽然 Q&A 第 10 条说以 20px 为准），这 256 个匹配只剩 **41 个（16%）**，46.79% 会大幅回落。
2. 不能靠"整体外扩/收缩框"修好——偏移量只有 1–3px，而误差是形状性的。真要提升，需要**针对 gnd/v 重新回归框**，或按符号模板生成框。
3. 这条与 codex 的判断一致：**50% 量级只能作为带假设的诊断方向，不能当正式分数**；此外还多了一层"阈值敏感性"。
