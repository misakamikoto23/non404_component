提交内容
提交内容分为两部分，分别是数据说明文档与数据。
1.数据说明文档：介绍数据来源、数量、许可或授权情况、及必要的使用说明。
2.数据：每张原理图对应一个统一 case_id，并提供同名原图、标注 JSON文件（与赛题输出结果JSON相同的格式）。每支参赛队伍提交的图片/案例总数不得少于20个，且不得与赛题提供的200个训练数据重复；具体命名与目录结构见“六、赛题提交格式说明”。
提交地址与时间
数据在评测平台进行提交（http://competition.nctieda.com:30080)，具体的提交入口后续会在QQ、Q&A文档中进行通知。
数据提交截止时间为2026年11月08日23时00分；截止时间前可多次提交，并以评测平台记录的最后一次成功提交的版本为准。2026年11月02日23时00分前提交的数据（截止时间前一周），经确认符合要求后，将选取一部分（每支队伍原则上不超过10个）加入到最终的测试数据集。

本赛题不限制数据来源。参赛队伍可通过开源渠道收集数据，也可使用自主构建的自有数据。
有效案例判定标准
参赛队伍提交的案例被认定为有效案例，须同时满足以下要求：
至少包含 1 个有效 IC。有效 IC 必须能够在原始电路图或原始资料中核验，且属于原始电路功能组成。
IC 标注完整。IC 名称、型号或可识别标识应完整，全部实际使用的 pin 原则上均应标注。
IC 实际参与电路。IC 须至少通过规定数量的有效 pin 与其他有效元件、端口或电气网络形成可核验连接。
有效元件不少于 5 个。有效元件是对电路功能、供电、保护、滤波、接口、偏置、检测或信号处理具有独立且可核验作用的器件。孤立、重复、虚构、占位或无实际意义的元件不计入。
有效连接关系不少于 5 个。连接关系须形成真实电路结构并可由原始资料核验；孤立导线、重复连接、虚构连接、装饰性线段及无电气意义的线段不计入。
有效连接关系统一按唯一电气网络（net）计数：电气上连续且等电位的一组端点计为 1 个有效 net；同一 net 的序列化、折线分段、跨页引用展开、junction节点展开或 endpoint-pair 枚举均不增加计数。仅当存在明确电气隔离或经有效器件形成新的网络时，方可另计 1 个 net。机器评测以规范化 net 标识及端点集合去重后的结果为准。
案例须形成具有实际意义、能够独立核验的电路结构。元件、pin、net 及其对应关系均应与原始图一致。
单个 IC 的最低有效 pin 数按 IC 总 pin 数 N 分段计算（同一 pin 仅计 1 次），具体如下：
N ≤ 16：不少于 max(3，向上取整(N × 20%))；17 ≤ N ≤ 32：不少于 max(5，向上取整(N × 20%))；33 ≤ N ≤ 64：不少于 max(8，向上取整(N × 15%))；65 ≤ N ≤ 144：不少于 max(12，向上取整(N × 10%))；N ≥ 145：不少于 max(16，向上取整(N × 8%))。计算结果不得超过该 IC 在原始电路中实际使用的 pin 数；若原始资料能够证明器件本身仅使用较少 pin，可提交依据进入人工复核，但不得通过选择高 pin 数器件规避有效连接要求。
上述任一项不满足，或与赛题提供的200个训练数据重复的案例，将被判定为无效案例，并不会被计分。
标注数据评测流程
标注数据评测采用“规范与有效性自动检查 + 形成有效数据池 + 达到20例后实施质量评测/人工抽检”的方法。流程如下：
JSON/Schema、规范与有效性自动检查
形成有效数据池
计分资格判定与质量评测/人工抽检
下面对流程中的每个步骤做出细化说明
JSON/Schema、规范与有效性自动检查
所有提交案例首先依据“有效案例判定标准”和现有数据规范开展有效性、格式及结构自动检查，主要包括：
JSON 语法、必填字段、数据类型及枚举值符合指定 Schema；
元件、pin、net、端点及连接 ID 唯一，引用关系存在且一致；
连接关系经拓扑规范化后计数；系统应合并同一 net 的分段、别名、跨页引用及 endpoint 展开，并对端点集合去重；
元件数量、有效 net 数、IC 总 pin 数及有效 pin 数可由结构化数据重复计算，申报值与复算值一致；
不存在重复连接、无效引用、统计虚增、循环引用或结构损坏；
文件命名、目录结构、图片格式及其他提交要求符合规定。
不符合与赛题提供的200个训练数据不重复的要求、自动检查失败，或关键统计字段无法由规范化数据复算的案例，不计入有效数据池。仅自动检查全部通过的案例进入有效数据池。队伍的有效数据池达到至少20例后，方具备计分资格，并按有效数据池规模确定质量评测/人工抽检量。
有效数据池、计分资格与人工抽检
各支队伍提交的案例经规范与有效性自动检查后，符合要求的案例形成有效数据池。有效数据池少于20例时，不具备计分资格，不进入质量评测/人工抽检，也不产生计分结果；有效数据池达到至少20例后，方进入质量评测/人工抽检。对于抽检合格的批次，有效数据池内的全部有效案例被计分。
质量评测/人工抽检比例与质量要求
抽检范围：仅对已具备计分资格（有效数据池至少20例）的队伍实施质量评测/人工抽检。抽检量为 max(20，向上取整(有效案例数×10%))。抽取过程采用固定随机种子的方式复现。
F1 计算口径。连接关系质量以 Precision、Recall、F1 为核心。每个抽检案例在规范化 net 层面分别计算 TP、FP、FN：Precision = TP/(TP+FP)，Recall = TP/(TP+FN)，F1 = 2PR/(P+R)。分母为 0 时按评测平台统一约定处理并记录。批次聚合采用微平均：先汇总全部抽检案例的 TP、FP、FN，再计算批次 Precision、Recall、F1。批次 F1 须不低于 95%，且任一单案例 F1 不得低于 85%。
其他质量检查。除 F1 外，同时检查：
元件、端点及 pin 标注是否正确，是否存在漏标、错标或无法核验内容；
IC 总 pin、有效 pin 与连接关系是否一致，案例内容与原始图及结构化数据是否一致；
是否存在重复、拆图、结构复制、等价拆分等情形。
质量要求：抽检案例中，连接关系批次平均 F1 不低于95%，且任一单案例 F1 不得低于85%，同时满足上述其他质量检查要求，方视为该批次抽检合格。若抽检未达到上述质量标准，则默认该批有效数据池中的数据全部不合格，不再继续检查或复核，该批数据不参与计分；抽检合格批次中，只有已进入有效数据池并符合现有质量要求的数据参与计分。
打分办法
总分为10分。
参赛队伍提交的图片/案例与赛题提供的200个训练数据不重复，并且满足提交格式要求，经自动检查进入有效数据池的案例数达到20例，方具备计分资格。
最终得分计算方法：参赛队伍提交的案例经自动检查后，符合规范和有效性要求的，纳入有效数据池。有效数据池达到20例及以上的队伍，方可进入质量评测人工抽检。仅当该批次抽检合格时，有效数据池内的全部有效案例计入该队伍的计分数量 Q_i；未达到上述条件的案例不计分。
最终得分：设第 i 支参赛队伍在有效数据池至少达到20例并通过质量评测/人工抽检后，可计入的符合质量要求的有效案例数量为 Q_i；所有具备计分资格的参赛队伍中的最高计入数量为 Q_max，则该队伍数据得分为 10 × Q_i / Q_max；当 Q_max 为0时，该部分得分均为0。
赛题提交格式说明
参赛队伍应将本次提交内容整理为一个 ZIP 压缩包，并通过赛题评测平台上传。提交包命名、数据集内部目录结构如下。
1. 提交包命名
（1）提交包命名：team_<队伍标识>_result_dataset.zip。文件名中的 dataset 标识不区分大小写，但建议统一使用小写。
压缩包内需同时包含规定的数据说明文档和 dataset/ 数据目录，仅修改文件名或仅附带部分数据文件，均不视为完成数据集提交。
2. 压缩包内部目录
提交包顶层应包含： dataset/目录，以及 dataset_description.pdf 或 dataset_description.docx。除本指南明确规定的内容外，评测平台要求的其他文件以平台页面说明为准。
数据说明文档
数据说明文档可以是pdf或者word文档格式。内容需介绍数据来源、数量、许可或授权情况、及必要的使用说明。其中需对使用的坐标系做出说明。
坐标系声明（必须）
- 必须在提交的数据说明文档中声明坐标原点与轴向。
- 绝对坐标（图内像素坐标）：统一以图片左上角为原点，x 轴向右增大，y 轴向下增大；一律为像素整数，粒度为 1 像素，不接受浮点数；元件框、引脚点、导线点、文本框等所有绝对坐标均适用；若历史绝对坐标为浮点数，须取整为像素整数后提交。
- 相对坐标（归一化坐标，如相对图片宽高的 0-1 比例、相对所属元件框的比例偏移）：允许浮点数，但必须在文档中声明归一化基准（相对于整图还是相对于元件框）。
4. 数据集案例文件命名
dataset/ 目录中的每个案例应使用统一且唯一的 case_id。同一张原理图的原图、JSON必须保持相同case_id，例如：case_0001.png、case_0001.json。
队伍标识和 case_id 应仅使用 ASCII 字母、数字和下划线，避免中文、空格及特殊符号；队伍标识在赛题范围内应可唯一识别队伍，case_id 在一次提交中不得重复。
