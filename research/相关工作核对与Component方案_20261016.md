# 相关工作核对与 Component 方案

## 1. 需要保留与收窄的判断

混合流水线适合作为本项目主线，但“所有成功系统都使用 VLM 校验”“连通性只能用确定性算法”都过强。论文中既有学习式连线预测，也有让 VLM 承担主要拓扑推理的方案。对我们选择低成本局部 VLM 复核，是基于当前数据、硬件、实测和比赛约束的工程判断。

| 工作 | 核实到的关键内容 | 对本项目的意义与限制 |
|---|---|---|
| [PCBnet，全文 III–IV](https://arxiv.org/html/2608.27923v1) | 元件和文本区域用 YOLOv11 定位，PaddleOCR 识字；文字配对结合距离、类别和对齐。表 III 的 YOLO+PaddleOCR ACC 为 93.67%，加入纠错和配对后为 98.57%。 | 把文字检测、识别、归属、纠错分开评估。98.57% 不是原生 OCR 的独立成绩。表中 ACC 与 1−CER 对应，不等于位号整串完全正确率。 |
| [DiagramNet，全文 3.2、4.3.3](https://arxiv.org/html/2605.01338v1) | 面向系统级框图，单类检测器定位，VLM 逐元件预测连接。60 张图用于 AMSBench 检测适配，该迁移实验排除了检测任务评估。 | 可借鉴定位与推理解耦及局部求解；不能据此保证我们的 60 张审核图已足够训练。它也不是“VLM 仅做校验”的证据。 |
| [OmniSch，全文 3.2、4.1](https://arxiv.org/html/2604.00270v4) | 源工程解析与渲染同步产生标注；传统基线包含检测、OCR 与文字归属。部分工具化 VLM 实验提供 GT 初始框。 | 位号、值、引脚文字需要分角色关联。给定正确初始框的成绩，不能当作实际检测流水线成绩。源文件自动导出更适合作为减少人工标注的长期方向。 |
| [Netlistify 官方代码](https://github.com/NYCU-AI-EDA/Netlistify) | 主体采用 YOLOv8、ResNet 方向识别和改造的 DETR 预测连线，并非 VLM 校验框架。当前公开推理入口还读取组件标签框，不能视作已接好实际检测与 OCR 的完整竞赛流水线。 | 说明方向和端子关系值得单独处理，也说明连通性可以采用学习式模型。未将用户稿所述“二维卷积检测交点”列为已确认的自身核心方法。 |

## 2. Component 环节的近期路线

目标仍是输出符号位置、类别、位号、参数、图上可见的型号，并为后续引脚和网络处理提供可追溯的身份。地、电源和部分端口允许没有独立位号，缺失字段保留空值。

### 2.1 检测与 OCR 并行，但 OCR 内部也应拆两步

```text
原图 ──→ YOLO：元件候选 ──→ ResNet：类别候选 ──┐
     └─→ 文本检测：文字位置 ──→ 局部OCR：原文 ──┤
                                              ↓
                             文字角色解析与元件关联
                                              ↓
                            大小框冲突检查与局部重检
                                              ↓
                               必要时由 Qwen 复核
```

“全图 OCR”应理解为覆盖全图的文字检测与局部文字识别，不是把缩小后的整张原理图直接送进一个文字识别器。先使用现成 PaddleOCR 文本检测建立基线；若漏字或误检明显，再对照独立文字检测器，不先假设需要另训 YOLO 文本模型。

保留文字多边形、方向、分数、原图坐标与原文；对小字和竖直文字局部补识别。文字分为位号、参数、型号、引脚号/名称、网络标签和说明文字，不能把任意数字都当作元件值。

### 2.2 关联采用多项证据，允许不匹配

将同列、同行且紧邻的位号和参数组成文字组，结合距离、文字高度、方向、元件类型兼容性及分区，进行区域内整体匹配。位号、参数、型号使用不同字段槽位；类别前缀只作证据，避免 ResNet 错误被反过来当成 OCR 正确的依据。

程序内部 ID 与图上位号分离。多单元符号保留各自位置及 unit，同时关联到 physical_reference；不因重复出现同一实体位号就直接清空。网络标签也不能按普通位号的唯一性处理。

### 2.3 OCR 帮助检查框的完整性

- 大框覆盖多个独立符号及多个位号组：产生“可能合并过度”的冲突，触发局部重检。
- 多个小框位于同一完整器件轮廓内，并共同对应一个标注组：产生“可能拆分过度”的冲突。
- 孤立高可信位号没有匹配元件：在附近找漏检，不能只凭文字凭空建立器件。
- 符号类别与文字语义冲突：同时保留两方证据，复核归属或分类。

电阻网络、光耦、多单元运放、连接器引脚都可能打破简单的一位号一图形规则。Qwen 应查看整个冲突组及干净上下文，从已有候选中选择，并允许不确定；不先依赖它自由生成精确框坐标。

## 3. 与后续 Pin/Net 环节的接口

颜色提取可用于当前彩色图的快速候选生成，但先检查图纸配色。红色也可能是整个符号轮廓，不能把红色像素直接当作引脚；其他来源可能是黑白图。保留灰度或学习式分割的后备路径。

元件遮罩仅用于专门的导线分析副本。不能简单把检测 bbox 全涂白后认为剩余拓扑天然正确：检测框可能覆盖引脚、引线或穿过附近的真实导线。应保存原始局部、引脚候选和遮罩边界的导线交点，最后恢复 pin–wire 关联。光耦内部 LED 也不能直接当独立外部元件和外部网络处理。

NetHypergraphF1 是 net 所包含的 pin 集合的比较；PCBnet 的连接准确率定义为正确恢复的 pin-to-pin 连接比例。两者不能直接换算。本地赛题权重与字段要求见[现有调研](PCB调研报告.md)。Component 的位号、引脚身份错误会向后传播，因此不能只按单项评分权重决定开发投入。

## 4. 建议的最小验证

1. 固定现有 YOLO 与 ResNet，在未用于训练的图上输出文字检测框、识别原文以及文字到元件的关联线。
2. 对照现有最近距离关联与文字组整体匹配，分别统计漏字、识错、配错、位号完全匹配和可见型号完全匹配。
3. 增加边框及大小框冲突处理，统计三类错误减少多少，同时统计正常元件被误删多少；不只报告总体框数变化。
4. 只有仍存在冲突的区域进入有预算的 Qwen 影子复核；独立保存建议，验证后再决定是否自动采用。
