一、赛题名称
AI驱动的PCB原理图自动解析
二、命题单位
芯粒CAD和制造浙江省工程研究中心，比昂芯科技有限公司
三、赛题背景
传统PCB原理图设计高度依赖人工绘制与整理，流程繁琐、迭代周期长、
人为误差率高。当前大量硬件开源资料、设备图纸、芯片参考设计均以PDF、
PNG等静态图像格式存储，无法直接编辑复用与工程导入，极大限制了电路设
计数字化、自动化落地。
近年来，依托人工智能技术实现原理图智能化解析，已成为PCB设计EDA
领域的重要研究方向，整体方案主要包含三类技术体系：
第一，传统机器视觉方案。依托边缘检测、霍夫变换、骨架提取、形态学
处理、连通域分析等算法，实现导线、器件轮廓、节点的基础分割与提取，结
合模板匹配完成常规标准器件识别。
第二，深度学习检测与分割方案。基于YOLO、Faster R-CNN、Mask R-
CNN、U-Net等主流视觉模型，实现元器件目标检测、引脚点位分割、导线区
域语义分割，结合CRNN、EasyOCR等文字识别算法完成位号、参数、引脚文
本提取，通过距离匹配、IOU匹配、空间方位约束实现器件与文字关联绑定，
有效提升复杂图纸的识别鲁棒性。
第三，多模态大模型融合方案。依托视觉大模型、图文理解模型的通用感
知能力，结合EDA专业先验知识，实现非标器件、模糊图纸、复杂拓扑、歧义
标注的智能理解，弥补传统CV算法泛化性差、规则固化的缺陷，提升复杂真实

场景下的电路解析精度。
在基础电路解析方面工业界和学术界都开展了大量工作，并取得突破。但
对复杂PCB原理图识别与解析，行业仍存在显著短板和诸多挑战，技术难点包
括下面几个方面。
一是密集器件识别精度不足。现有模型对高密度排布、器件重叠、局部遮
挡、小型贴片器件场景识别误差大，极易出现器件漏检、误检、类别混淆问题，
难以满足工程级精度要求。
二是引脚定位与关联精度低。传统方案仅能识别器件整体包围盒，无法精
准区分多引脚器件的引脚坐标、引脚编号对应关系，普遍存在引脚错位、引脚
漏识别、引脚与器件错绑定的问题。
三是文字-器件关联容错性差。常规IOU匹配、就近匹配算法在文字扎堆、
标注倾斜、跨器件文字干扰场景下极易错配，无法精准实现位号、参数、引脚
名与对应器件的语义绑定。
四是复杂拓扑电气解析能力弱。现有算法难以精准区分导线物理交叉与电
气连通，对T型节点、十字节点、多分支走线、断线失真图纸的连通性判断误
差大，易出现错连、漏连、虚假网络。
针对前述技术难点和挑战，本赛题聚焦复杂PCB原理图的识别与自动解析
技术，为解决这些难点提供创新平台。图一用一个示例说明本赛题需解决问题
的特点，包括下面两个方面。
1）赛题需要解析的电路规模大，元器件多，单一器件引脚多并密集，连接
关系复杂，文字扎堆易受干扰，飞线抑制难度大。
2）赛题要求完成丰富的信息识别，包括元器件（元件key、类型、名称、
value 和bbox），每个元器件上的 pin角（pin number、pin name和pin坐标），电
路连接关系（每个net连接了哪些 pins，以及该 net 对应的线段集合）。另外为
准确完成本赛题任务，需要完成文字识别，这对复杂的PCB场景有很高的难度。

四、赛题描述
（一）赛题任务
本赛题任务是给定一张PCB电路原理图图片，参赛系统需要识别出结构化
原理图信息，并输出为规定的 JSON 格式。
1.输入：电路原理图图片。赛题提供的数据集为PNG格式，参赛队伍
可根据需求转换成其它格式以用于更多处理，赛题对此不做约束。
参赛系统需要预测三类信息：
a)‘components’：图中的元器件实例，例如 `U1`、`R3`、`C12`，包
含类别、文本信息和 bbox。
b)‘pins’：每个元器件的 pin，包括pin number、pin name和pin坐标。
c)‘nets’：电路连接关系，包括每个net连接的pins，以及该 net 对应
的线段集合。

a)元件是否识别正确。
b)元件 type / text / bbox 是否正确。其中 IC 比较 ‘Name’，电阻和电容比较

c)pin number / pin name / pin position 是否正确。

e)线段是否在对应的 matched net 内画对。
f)Token消耗量。
本赛题不限制实现方法，参数队伍可应用机器学习算法、计算机视觉算法、
多模态大模型等。

(二) ComponentF1
Component 直接用 key 匹配，例如 GT 的 `U3` 只和 Pred 的 `U3` 比较。一
个 component 需要同时满足以下条件才算正确：
a)key 匹配；
b)type 正确；
c)bbox 坐标误差在阈值内，默认阈值为‘20 px’；
若需要比较文本，则文本严格一致。
文本比较规则：
a)‘ic’：比较 ‘Name’；
b)‘resistor’、‘capacitor’：比较 ‘value’；
c)其他类别：不比较文本。

8
(三) PinF1
Pin 先按 component key 匹配，再按 pin number 匹配。一个 pin 需要满足：
a)Pin name 正确；
b)pin number 正确；
c)pin 坐标距离在阈值内，默认阈值为‘5 px’。pin 坐标和引脚连接方式见附录三
的详细说明。
(四) NetHypergraphF1
每个 net 被视为一个 pin set。评测时根据 pred net 和 GT net 进行匈牙利匹配，之
后计算每个 net 中的元件 pin 是否正确出现。
(五) NetLineF1
Line 只在 matched net pair 内比较。每条 `edge_i` 作为一条线段检测目标。若
Pred segment 与 GT segment 的两个端点距离足够接近，默认阈值为 `5 px`，则
认为该线段检测正确。
(六) 注意事项
a) Component key 很重要，错误的 key 会影响 component、pin 和 net 的评分。
b) 字符串采用严格匹配，`10k`、`10K`、`10 k` 会被视为不同字符串。
c) Net key 本身不要求和 GT 一致，但`hyperGraph`中的 pin 连接关系需要正确。
d) 所有坐标单位均为图片像素。
e) 赛题会提供评测代码供参数队伍评测算法。完整的公式、边界情况和诊断指

输出⽬标 JSON 必须包含三个顶层字段：
a)component：以元件 designator 为键，描述每个元件的类别、名称、取值

b)pins：以元件 designator 为键，下属 pin_ ，描述引脚名称和连接点坐标。

坐标系沿用原始 ParsedJson 的左下角坐标系：x 轴向右增大，y 轴向上增大。
bbox 的格式为 [x1, y1, x2, y2] ，其中 (x1, y1) 为左下角坐标， (x2, y2) 为右上角
坐标。

8. hyperGraph 相关 JSON 格式示例（带飞线）
什么是飞线？
飞线指：原理图上存在多个同名但物理位置分散的非 VCC/GND 测试点/网络标
签元件，它们通过同一个 net 名称在逻辑上连接在一起。与这些同名元件直接
相连的其它元件引脚，即使没有实际导线画在一起，也属于同一个 net。
在本案例中， RUN_1 、 RUN_2 、 RUN_3 、 RUN_4 是 4 个同名的测试点/网
络标签，分别位于原理图的不同位置。它们共同构成了 RUN 网络：
 RUN_1 与 U3.26 直接相连；
 RUN_2 与 U5.17 直接相连；
 RUN_3 与 R8.1 直接相连；
 RUN_4 与 SW2.1 直接相连。
虽然 U3 、 U5 、 R8 、 SW2 之间在原理图上没有画导线，但由于它们都连接
到了同名 RUN 网络，因此逻辑上属于同一个 net，这就是飞线关系。

RUN net 涉及的各个引脚。这些点分布在图纸不同位置，通过 RUN 网络在逻辑

飞线特点总结
a) 同名分散元件：飞线 net 的核心是多个同名网络标签/测试点，如 RUN_1 、
RUN_2 、 RUN_3 、 RUN_4 。
b) 逻辑连接而非物理连接：这些同名元件在图纸上没有导线相连，但共享同
一个 net 名称。
c) edges 为点状线段：由于飞线没有实际 wire，每个连接点在 edges 中表现为
一条零长度线段（起点与终点相同）。
d) hyperGraph 包含所有相关引脚：不仅包含同名测试点本身，还包含与它们
直接相连的所有元件引脚。
注意事项
a) VCC/GND 等电源/地网络虽然也有多个同名元件，但通常被视为普通电源
网络，不按飞线处理。飞线特指非 VCC/GND 的同名网络标签/测试点。

b) 如果同名测试点只有一个，则该 net 为普通 net，不形成飞线。
c) 飞线 net 的 hyperGraph 必须包含所有逻辑相连的引脚，遗漏任何一方都会
导致连接关系错误。

附录四、常见注意事项
1. Component key 非常重要。`U3` 写成 `U8` 会导致该 component、其 pins、相
关 nets 都难以得分。
2. Pin key 要稳定使用 `pin_<pin_number>`，因为 pin matching 直接使用 pin
number。
3. `hyperGraph` 中的 pin 写法应和 pin key 对齐，例如 `U1.2` 对应
`pins.U1.pin_2`。
4. Net key 本身不要求和 GT 一致，但 net 的 `hyperGraph` pin set 要正确。
5. Line geometry 必须放在正确 net 的 `edges` 下；画到错误 net 里不会因为几何
位置接近而得分。
6. 字符串采用严格匹配，`10k`、`10K`、`10 k` 是不同字符串。
7. 坐标单位为图片像素，默认 pin 和 line 阈值都是 `5 px`。
